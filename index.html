Power BI · Retail
Retail Sales Dashboard
Full walkthrough from a blank .pbix file to a finished executive dashboard with live DAX KPIs and drill-through pages.
Power BI SQL Excel
1
Requirement Gathering
Blank file → Understanding what the dashboard needs to answer
Started with a blank .pbix file and a list of business questions: Which products are driving revenue? Which regions are underperforming? What does YoY growth look like? Writing down the questions first before touching any data helped shape the entire design.
2
Data Source & Power Query
Loading and cleaning the raw sales CSV in Power Query
Imported the raw Excel sales flat table. Used Power Query to remove blank rows, fix date formats, split a combined Region-Country column, and rename fields to something readable. Also created a Date dimension table here using M code so I could enable proper time intelligence later.
3
Data Modelling
Building the star schema and setting up relationships
Connected the fact sales table to the Date, Product, Region, and Customer dimension tables with one-to-many relationships. Made sure all relationships were active and filter direction was set correctly so DAX would behave as expected.
4
DAX Measures
Writing the KPI measures: Total Sales, YoY%, Running Total, Top N
Created a dedicated Measures table. Key measures included: Total Sales, Gross Margin %, YoY Growth using SAMEPERIODLASTYEAR, Running Total using CALCULATE + DATESINPERIOD, and a Top 10 Products measure using RANKX. Each measure was tested in a table visual before being placed on the report canvas.
5
Report Design
Building the canvas: KPI cards, bar charts, map, and drill-through
Designed 3 pages: an Executive Summary with KPI cards and a clustered bar by region; a Product Analysis page with a matrix and waterfall chart; and a Drill-Through page that activates when you right-click any product row. Used a dark theme and consistent colour coding for positive/negative values.
6
Review & Publish
Testing filters, fixing cross-filter behaviour, publishing to the web
Ran through every slicer combination to check for unexpected blank values or broken measures. Fixed one cross-filter issue where the product matrix was filtering the date slicer. Published to Power BI Service and set up a public embed link.
What I learned

Proper star schema setup makes DAX dramatically easier. The biggest time sink was always Power Query, not the visuals. Writing requirements first saved me from redesigning the canvas halfway through.

Python · Retail Analytics
ABC / XYZ Assortment Classifier
A Python script that automatically categorises every SKU by revenue contribution (ABC) and demand volatility (XYZ) — helping decide what to keep, grow, or cut.
Python Pandas Excel
1
Problem Definition
Why ABC/XYZ? Understanding the classification logic
ABC classifies SKUs by cumulative revenue share: A items = top 70%, B = next 20%, C = bottom 10%. XYZ adds a volatility layer using coefficient of variation on weekly sales. A-X items are your stars; C-Z items are candidates for removal. I read up on this in retail operations articles before writing any code.
2
Data Preparation
Loading and reshaping weekly sales data with Pandas
Loaded a multi-week sales CSV. Used groupby to aggregate by SKU and week, then pivoted to a wide format (SKUs as rows, weeks as columns). Handled missing weeks by filling with 0 — an important decision since absent weeks are genuinely zero-sales, not nulls.
3
ABC Classification
Calculating cumulative revenue share and assigning tiers
Summed total revenue per SKU, sorted descending, calculated cumulative percentage, then used pd.cut() with the 70/90/100 breakpoints to assign A, B, or C. Verified the output against a manual calculation in Excel first.
4
XYZ Classification
Calculating coefficient of variation for demand stability
For each SKU, calculated std / mean across all weeks to get the CV. Buckets: X = CV < 0.5 (stable), Y = 0.5–1.0 (variable), Z = >1.0 (highly erratic). Combined with ABC to create a 9-cell matrix (AX, AY, AZ, BX... CZ).
5
Output & Export
Exporting a colour-coded Excel report with openpyxl
Used openpyxl to write the classified DataFrame to Excel with conditional formatting — green for AX, yellow for BY, red for CZ. Added a pivot summary sheet showing counts and revenue per classification bucket. This made the output immediately usable without needing Python knowledge.
What I learned

The hardest part was deciding how to treat missing data — zero vs null makes a huge difference in CV calculation. openpyxl for formatted Excel output was a new skill that made the results much more presentable.

Tableau · Sales Analytics
Sales Performance Dashboard
Built on the Superstore dataset — a full Tableau project from connecting data to publishing an interactive dashboard with YoY comparisons and regional breakdowns.
Tableau SQL
1
Connect & Explore
Connecting Tableau to the Superstore Excel file and exploring dimensions
Connected Tableau Desktop to the Sample Superstore Excel workbook. Spent time in the Data Source tab understanding the schema — Orders, Returns, and People tables. Created a relationship join between Orders and Returns on Order ID.
2
Calculated Fields
Creating YoY growth, profit ratio, and running total calculations
Used Tableau's calculation editor to write: YoY Sales Growth using LOOKUP(ZN(SUM([Sales])), -1), Profit Ratio as SUM([Profit])/SUM([Sales]), and a Running Total using RUNNING_SUM. Table calculations in Tableau behave differently from DAX — this took some trial and error to get right.
3
Sheet Building
Building individual chart sheets before assembling the dashboard
Created 6 separate sheets: KPI bar chart, regional map, category breakdown tree map, monthly trend line, Top 10 customers table, and a scatter plot of Profit vs Discount. Building sheets separately first makes dashboard assembly much faster.
4
Dashboard Assembly
Laying out sheets, adding filters, and setting up actions
Used a fixed 1200×800 layout. Added a segment filter and a year filter as quick filters. Set up filter actions so clicking any region on the map filters all other charts. Also added a URL action on the customer table (placeholder for a CRM link).
5
Publish
Publishing to Tableau Public and embedding
Published to Tableau Public. Tested the embed on a blank HTML page to make sure all interactive elements worked in the browser. The map visual had a slight render lag on first load — a known Tableau Public limitation.
What I learned

Tableau's table calculations are powerful but confusing at first — understanding "compute using" was the key unlock. Building sheets before the dashboard is a workflow habit I've kept ever since.

Databricks · Data Engineering
Medallion Data Pipeline
A personal project to learn data lakehouse architecture — ingesting raw CSV sales data through Bronze, Silver, and Gold layers in Databricks, feeding a Power BI report.
Databricks PySpark Power BI
1
Architecture Design
Planning the Bronze → Silver → Gold layer structure
Designed the three-layer architecture on paper first. Bronze = raw data landed as-is (no transformations, append-only). Silver = cleaned, typed, and deduplicated. Gold = aggregated business-ready tables (daily sales by region, top products by month). Mapped out which columns belong in each layer before writing any code.
2
Bronze Layer
Landing raw CSV files into Delta tables with autoloader
Used Databricks Autoloader (cloudFiles) to ingest CSV files from a mounted storage path into a Delta table. Autoloader handles schema inference and new file detection automatically. Added ingestion_timestamp and source_file columns for auditability.
3
Silver Layer
Cleaning, typing, and deduplicating with PySpark
Read from Bronze Delta table. Applied: cast date strings to DateType, strip whitespace from product names, filter out rows where quantity ≤ 0 (data quality issue), and deduplicate using dropDuplicates on order_id + product_id. Wrote the result to a Silver Delta table with MERGE to handle incremental updates.
4
Gold Layer
Aggregating business metrics into fact tables
Created two Gold tables: daily_sales_by_region (date, region, total_revenue, total_units, avg_order_value) and product_performance (product_id, product_name, total_revenue, rank). Used window functions for running totals and rankings within PySpark SQL.
5
Power BI Connection
Connecting Power BI to the Gold Delta tables via Databricks connector
Used the native Databricks connector in Power BI Desktop (Import mode). Connected to the Gold layer tables, built a simple star schema, and created 4 DAX measures on top. Scheduled a daily refresh to keep the dashboard current.
What I learned

Delta Lake's MERGE statement was the most valuable new concept — it handles upserts cleanly without needing to manage deduplication manually. The medallion architecture makes debugging much easier because you can always trace a Gold value back to its raw Bronze source.

Power BI · E-Commerce
Customer Behavior Dashboard
Built to practise DAX time intelligence — tracks customer segments, purchase frequency, basket size, and identifies potential churn signals.
Power BI SQL
1
Questions First
Defining what "customer behaviour" questions to answer
Listed the questions before opening Power BI: Who are our top 20% of customers by revenue? How often do customers return? What's the average basket size by segment? Which customers haven't bought in 90+ days? These became the measures I needed to build.
2
RFM Segmentation in SQL
Pre-calculating Recency, Frequency, Monetary scores in SQL before loading
Wrote a SQL query to pre-calculate RFM scores (Recency = days since last purchase, Frequency = number of orders, Monetary = total spend) and assign segment labels (Champion, Loyal, At Risk, Lost). Loaded this as a separate Customer Segments table in Power BI.
3
DAX Time Intelligence
DATESINPERIOD, PARALLELPERIOD, and rolling 30/90 day measures
This was the main learning goal. Built: Sales Last 30 Days, Sales Last 90 Days, MoM Growth %, Customer Count Last 30 Days, and a Churned Customers measure (customers who bought in the previous 90 days but not the last 30). CALCULATE + DATESINPERIOD is the core pattern for rolling windows.
4
Report Design
Segment overview page + individual customer drill-through
Page 1: segment distribution donut, KPI cards for each segment's revenue share, and a line chart of new vs returning customers over time. Page 2: drill-through from any customer segment to see individual customers in that group with their full purchase history.
What I learned

Doing RFM segmentation in SQL before loading into Power BI (rather than trying to do it all in DAX) is dramatically simpler. DAX time intelligence requires a proper Date table with no gaps — this bit me early on and taught me to always build the Date table first.

Python · Retail · In Progress
Availability Gap Finder Web App
An actively-built multi-phase web app that identifies which SKUs are missing from a retailer's range compared to competitor availability — with file uploads, saved reports, and month selection.
Python SQLite Vanilla JS
1
Phase 1 — Core Logic
Pure Python HTTP server + gap calculation engine
Built the backend using Python's built-in http.server module (no frameworks). The gap engine takes two CSV inputs — our range and a competitor range — and returns SKUs present in competitor but missing from ours, grouped by category. All served as JSON over a simple REST-style API.
2
Phase 1 — Frontend
Vanilla JS frontend with file upload and results table
Built the UI in pure HTML/CSS/JS — no frameworks. Two file inputs (our file, competitor file), a submit button that POSTs to the Python server, and a results table that renders the gap list dynamically. Learned how to use the Fetch API and handle multipart form data.
3
Phase 2 — Persistence
Adding SQLite to save reports and enable history
Integrated SQLite so each gap analysis run gets saved with a timestamp and report name. Users can now load any past report without re-uploading files. Also added a "replace file" feature to update the stored range without clearing the report history.
4
Phase 2 — Month Selection
Filtering gap results by month for trend comparison
Added a month dropdown that filters the gap results to a selected period. This lets you compare: were the same SKUs missing in March and April, or did the gap shift? Involved restructuring the SQLite schema to store results with a period field.
5
Phase 3 — Planned
Charts, export to Excel, and multi-user support
Next phase: add a Chart.js visualisation of gap trends over time, an Excel export button using openpyxl, and basic session handling so multiple users can have separate report histories. Still in progress.
What I learned

Building a full-stack app without any framework forces you to understand exactly what frameworks are abstracting. Routing, request parsing, and file handling in raw Python is tedious but now I understand it deeply. SQLite is surprisingly capable for a single-user web app.
