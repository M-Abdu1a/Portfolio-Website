Process

1
Requirement Gathering
Blank file to business questions

Started with a blank .pbix file and a list of business questions: which products drive revenue, which regions are underperforming, and what YoY growth looks like. Writing the questions first shaped the report design.

2
Power Query
Cleaning the sales source

Imported the raw Excel sales flat table, removed blank rows, fixed date formats, split a combined Region-Country column, renamed fields, and created a Date dimension for time intelligence.

3
Data Model
Building the star schema

Connected the fact sales table to Date, Product, Region, and Customer dimensions with one-to-many relationships and checked filter direction so DAX measures behaved correctly.

4
DAX
Writing KPI measures

Created measures for Total Sales, Gross Margin %, YoY Growth, Running Total, and Top 10 Products. Each measure was tested in a table visual before being placed on the report canvas.

5
Report Design
Executive, product, and drill-through pages

Designed an Executive Summary, Product Analysis page, and Drill-Through page. The dark theme keeps the report consistent with the portfolio while giving positive and negative values clear contrast.

6
Testing
Checking filters and publish behavior

Ran slicer combinations, checked for blanks, fixed one cross-filter issue, and prepared the dashboard for publishing.

Technical Artifacts
DAX measure
Total Sales = SUM('Sales'[SalesAmount])
SQL snippet
SELECT Region, SUM(Sales) AS TotalSales
FROM Sales
GROUP BY Region;
What I learned

Proper star schema setup makes DAX dramatically easier. The biggest time sink was Power Query and model preparation, not the visuals.
